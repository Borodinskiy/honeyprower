# HoneyForge

Центр управления парком ловушек-приманок (honeypot) и агент-ловушка.
Оператор (Blue Team / SOC) создаёт ловушки на сайте, разворачивает их агентами
на удалённых хостах и в реальном времени видит активность атакующих.
Исходная постановка задачи — `docs/project_description.pdf`.

## Архитектура

```
                    ┌──────────────────────── Центр (Go) ────────────────────────┐
  браузер ─────────►│  :8080 веб-сервер ──┬─ статика (login/dashboard/script/css) │
  оператора         │                     └─ /api/* ──прокси──► :8081 API ──► PostgreSQL
                    └──────────────────────────────▲─────────────────────────────┘
                                                    │  POST /api/ingest  (события)
                                                    │  POST /api/heartbeat (жив)
                            односторонний канал ─────┘  авторизация по токену ловушки
                                                    │
  атакующий ──► сервис-приманка ──► ┌────────── Агент-ловушка (Rust) ──────────┐
                                    │  один бинарник, конфиг едет рядом с ним   │
                                    │  поднимает ловушку, шлёт телеметрию       │
                                    └───────────────────────────────────────────┘
```

Ключевой принцип: **канал односторонний и скрытный**. Агент только шлёт телеметрию в центр;
из центра к агенту ничего не идёт. Чтобы изменить ловушку — оператор меняет её на
сайте, скачивает новый конфиг и перезапускает агент. Конфиг (с токеном, открытым ключом
сервера и параметрами stealth-транспорта) путешествует вместе с бинарником.

- **Скрытный транспорт (Stealth Transport)** — агент отправляет пакеты телеметрии без сохранения
  следов в таблицах соединений ядра (`ss` / `netstat`). Доступны транспорты:
  - `http_nolinger` — отправка через сокет с `SO_LINGER=0`. При закрытии сокета ядро отправляет `TCP RST`,
    минуя состояние `TIME_WAIT`.
  - `udp_burst` — бессессионный одиночный UDP-пакет без вызова `connect()`.
  Телеметрия маскируется под легитимный служебный веб-трафик (маршруты `/cdn-cgi/rum`, `/v1/rgstr`, `/api/v2/metrics`),
  а центр всегда отвечает статусом `204 No Content` для предотвращения зондирования.
- **Асимметричное шифрование Envelope (X25519 + ChaCha20-Poly1305)** — каждое сообщение сжимается
  `gzip` и запечатывается в криптографический конверт (`[KeyID: 8B] || [Ephem_PK: 32B] || [Nonce: 12B] || [Ciphertext+Tag]`):
  одноразовая пара `X25519` + HKDF-SHA256 derivation + ChaCha20-Poly1305. Одноразовый секретный ключ затирается в памяти
  через `zeroize`. Дисковый буфер при обрыве связи сохраняется в виде Base64-строк готовых шифрованных Envelope
  (без хранения открытого JSONL на диске агента).
- **Центр** (`main.go`, `internal/`) — сайт оператора, API, приём и расшифровка телеметрии, PostgreSQL
  (с автоматическим graceful fallback на in-memory хранилище при автономном запуске без СУБД).
- **Агент** (`agent/`, Rust) — компилируется в один бинарник, запускает одну ловушку
  из локального JSON-конфига. Классы: `banner`, `dialog`, `http`, `port_listener`,
  `tarpit`, `honeytoken`, `udp`. Поддерживает рандомизированный джиттер и piggybacking heartbeat.
- **Хранилище** (`internal/storage`) — интерфейс `Storage`; реализации `Postgres`
  (рабочая) и `Memory` (тесты и автономный режим). Схема и демо-данные (`migrations/*.sql`) применяются
  при старте в одной транзакции. Окно вычисления статуса `online` составляет 120 секунд с учетом джиттера.
- **Сессии оператора** (`internal/auth`) — токен в HttpOnly-cookie, срок 7 дней.

## Быстрый старт (docker-compose)

Поднимает весь стенд: центр + PostgreSQL + две демо-ловушки (Low и Medium).

```bash
docker compose up -d --build     # или: podman-compose up -d --build
```

- Сайт: http://localhost:8080 — вход `admin` / `admin`.
- Демо-ловушки на хосте: SSH-баннер `:2222` (low), fake-FTP `:2121` (medium).

Проверка сценария «атака → событие в центре»:

```bash
printf 'USER root\r\nPASS hunter2\r\nQUIT\r\n' | nc localhost 2121
```

На вкладке «События» появится захваченная пара логин/пароль, ловушка станет `online`.

## Создание ловушки на сайте

1. «+ Создать ловушку» → выберите класс и, по желанию, готовый шаблон (FTP, SMTP, Redis, HTTP-портал…).
2. Заполните параметры в форме. Она строится по описанию класса (`GET /api/classes`, поле `fields`):
   у каждого поля есть подсказка, редкие параметры убраны в «Дополнительные параметры»,
   правила / маршруты / ссылки-приманки — это списки с кнопками «добавить», ↑ ↓ ✕.
   Зависимые поля появляются сами (например, «IP в ответах» — только для DNS/SSDP).
   Для тонкой настройки есть «Редактировать как JSON»: ключи вне схемы сохраняются.
3. Сохраните. Центр проверит параметры по схеме (типы, допустимые значения, regex, hex)
   и укажет конкретное поле, если что-то не так; пустые ID honeytoken сгенерирует сам.
4. В открывшемся окне скачайте `config.json` (или `.zip` с инструкцией) и запустите
   агент на хосте-ловушке: `./honeyforge-agent config.json`.

|----------------------|---------------------|-----------------------------------------|
| `WEB_ADDR`           | `:8080`             | адрес веб-сервера                        |
| `API_ADDR`           | `127.0.0.1:8081`    | адрес API-сервера                        |

## API

Ответы — JSON, ошибки — `{"error": "..."}`. Операторские запросы авторизуются
cookie-сессией (или `Authorization: Bearer <token>`). Телеметрия агентов — токеном
ловушки в заголовке `X-HF-Token`.

### Оператор

| Метод  | Путь                     | Тело / назначение                       |
|--------|--------------------------|-----------------------------------------|
| POST   | `/api/auth/register`     | `{username,email,password}`             |
| POST   | `/api/auth/login`        | `{username,password}`                   |
| POST   | `/api/auth/logout`       | —                                       |
| GET    | `/api/auth/me`           | текущий оператор                        |
| GET    | `/api/classes`           | каталог классов ловушек (для формы)     |
| GET    | `/api/presets`           | готовые шаблоны ловушек                 |
| GET    | `/api/traps`             | список ловушек (со статусом online/…)   |
| POST   | `/api/traps`             | создать: `{name,class,bind,port,ports,params,enabled}` |
| GET    | `/api/traps/{id}`        | одна ловушка                            |
| PATCH  | `/api/traps/{id}`        | изменить поля                           |
| DELETE | `/api/traps/{id}`        | удалить (204; события каскадом)          |
| GET    | `/api/traps/{id}/events` | события ловушки                         |
| GET    | `/api/traps/{id}/config` | скачать `config.json` для агента        |
| GET    | `/api/traps/{id}/bundle` | скачать `.zip` (конфиг + инструкция)     |
| GET    | `/api/events`            | лента с фильтрами `trapId,type,src,since,limit` |
| GET    | `/api/stats`             | агрегаты для дашборда                    |

### Агент → центр (телеметрия и скрытные каналы)

| Метод | Путь              | Тело / назначение                                         |
|-------|-------------------|-----------------------------------------------------------|
| POST  | `/cdn-cgi/rum`    | Stealth Envelope (`X25519 + ChaCha20-Poly1305 + Gzip`)    |
| POST  | `/v1/rgstr`       | Stealth Envelope (`X25519 + ChaCha20-Poly1305 + Gzip`)    |
| POST  | `/api/v2/metrics` | Stealth Envelope (`X25519 + ChaCha20-Poly1305 + Gzip`)    |
| POST  | `/api/ingest`     | Одно событие телеметрии (legacy JSON, заголовок `X-HF-Token`) |
| POST  | `/api/heartbeat`  | Обновить «last seen» (legacy JSON, заголовок `X-HF-Token`)    |

Центр декодирует Envelope по префиксу `KeyID` (8 байт), находит ловушку, вычисляет общий секрет `X25519`
с её `priv_key`, расшифровывает и распаковывает сжатое Gzip-содержимое (`{"t": "...", "k": "ingest|hb", "e": [...]}`).
Все stealth-маршруты всегда возвращают статус `204 No Content` независимо от исхода, исключая возможность
зондирования периметра атакующим.

Небезопасные операторские запросы с чужого origin отклоняются (CSRF, 403);
каналы агентов (как legacy `/api/ingest`, `/api/heartbeat`, так и stealth-маршруты) из-под этой защиты исключены,
так как у них своя аутентификация по токену и криптографическому конверту, а не cookie.

## Автономный запуск (без Docker)

Сервер поддерживает graceful fallback на in-memory хранилище, если PostgreSQL не настроен или недоступен:

```bash
# 1. Сборка и запуск центра управления
go build -o honeyforge-server ./cmd/server/main.go
./honeyforge-server

# 2. Сборка агента
cd agent
cargo build --release
# Исполняемый файл: target/release/honeyforge-agent
```

## Тесты

```bash
go test ./...        # центр (Go)
cd agent && cargo test   # агент (Rust): протокол каждого класса ловушки
```

Интеграционный тест PostgreSQL запускается только при заданной тестовой БД
(создаёт и удаляет временную схему):

```bash
TEST_DB_DSN="postgres://postgres:postgres@localhost:5432/honeyforge?sslmode=disable" go test ./internal/storage/
```
