# HoneyForge Agent

Honeypot-агент на Rust. Собирается в один бинарник и держит все ловушки
своего хоста. Конфиг едет вместе с бинарником (JSON-файл рядом); из центра
ничего не приходит — канал односторонний, агент только шлёт телеметрию.
Поменять ловушки = поправить конфиг и запустить заново (центр делает это сам
при деплое хоста).

## Сборка

```bash
cargo build --release          # target/release/honeyforge-agent
```

## Запуск

```bash
honeyforge-agent [config.json]         # по умолчанию ./config.json или $HF_CONFIG
```

Конфиг и готовую команду запуска выдаёт центр при создании ловушки на сайте.

## Формат конфига

Один агент держит все ловушки своего хоста. Конфиг выдаёт центр (кнопка
«Развернуть» на странице хоста или `GET /api/hosts/{id}/config`):

```json
{
  "center_url": "http://127.0.0.1:8080",
  "transport": "http_nolinger",
  "stealth_paths": ["/cdn-cgi/rum", "/v1/rgstr", "/api/v2/metrics"],
  "jitter_s": 10,
  "traps": [
    {
      "token": "<токен ловушки>",
      "server_pub_key": "<X25519 ключ центра для этой ловушки>",
      "name": "SSH OpenSSH",
      "class": "ssh",
      "bind": "0.0.0.0",
      "port": 2222,
      "params": {}
    },
    {
      "token": "<токен другой ловушки>",
      "server_pub_key": "<её ключ>",
      "name": "FTP",
      "class": "dialog",
      "port": 2121,
      "params": { "greeting": "220 (vsFTPd 3.0.5)\r\n" }
    }
  ]
}
```

- Каждая ловушка шлёт события под своим токеном и ключом; у каждой свой
  heartbeat и свой файл буфера (`<buffer>-<KeyID>.dat`).
- Агент проверяет, что токены не повторяются, а порты не пересекаются
  (TCP и UDP — разные пространства), и занимает все порты до начала работы.
  Если какой-то порт занят, агент не стартует и пишет, какой и для какой
  ловушки.
- Старый формат с одной ловушкой по-прежнему читается:
  `{"center_url": ..., "token": ..., "server_pub_key": ..., "trap": {...}}`.

### Параметры Stealth-режима

| Параметр | По умолчанию | Описание |
|---|---|---|
| `server_pub_key` | `""` | 64-символьный hex открытого ключа `X25519` центра. При наличии активирует шифрование Envelope. |
| `transport` | `"http_nolinger"` | Механизм доставки: `"http_nolinger"`, `"udp_burst"`, или legacy `"http"`. |
| `stealth_paths` | `["/cdn-cgi/rum", "/v1/rgstr", "/api/v2/metrics"]` | Список URL-путей маскировки телеметрии под служебный CDN/web-трафик. |
| `center_udp` | `""` | Адрес центра (`host:port`) для отправки бессессионных датаграмм при `transport = "udp_burst"`. |
| `buffer_path` | `null` | Путь к файлу буфера. По умолчанию `$HF_BUFFER_PATH`, иначе `honeyforge-agent-buffer.dat` во временном каталоге. |
| `jitter_s` | `10` | Максимальная случайная добавка в секундах к интервалу heartbeat. |

## Бесследная доставка (Stealth Transport)

- **`http_nolinger` (SO_LINGER = 0)**: соединение создаётся через библиотеку `socket2` с установкой `socket.set_linger(Some(Duration::ZERO))` и заголовком `Connection: close`. После прочтения ответа `200/204` закрытие сокета принудительно вызывает отправку пакета `TCP RST` со стороны ядра. Сокет не переходит в состояние `TIME_WAIT`, поэтому после отправки соединение не остаётся в выводе `ss` и `netstat`.
- **`udp_burst`**: телеметрия отправляется одиночным UDP-пакетом через `UdpSocket::bind("0.0.0.0:0")` и прямой `send_to` без вызова `connect()`, не создавая постоянной сессии. Пачка, которая не помещается в датаграмму, делится на несколько конвертов. Центр принимает такие пакеты на `UDP_INGEST_ADDR`.
- **Маскировка**: запросы отправляются на случайные пути из списка `stealth_paths` (`/cdn-cgi/rum`, `/v1/rgstr`, `/api/v2/metrics`), мимикрируя под фоновый браузерный трекинг и сбор метрик. Центр всегда отвечает `204 No Content`.
- **Piggybacking**: при отправке реальных событий таймер heartbeat автоматически сбрасывается, исключая избыточный периодический трафик.

## Шифрование конвертов (Envelope Encryption)

Каждая порция телеметрии (`{"t": "<token>", "k": "ingest|hb", "e": [...]}`) упаковывается по техническому стандарту:
1. Исходный JSON сжимается алгоритмом `gzip` (RFC 1952).
2. Вычисляется `KeyID = SHA256(token)[:8]` (8 байт).
3. Агент генерирует одноразовую эфемерную ключевую пару `(ephem_sk, ephem_pk)` на кривой `X25519`.
4. Вычисляется общий секрет Диффи-Хеллмана: `shared_secret = X25519(ephem_sk, server_pub_key)`.
5. Симметричный 32-байтный ключ выводится через HKDF:
   `sym_key = HKDF-SHA256(secret=shared_secret, salt=KeyID, info=b"honeyforge-envelope-v1")`.
6. Сжатый буфер шифруется алгоритмом `ChaCha20-Poly1305` со случайным 12-байтовым `nonce`.
7. Одноразовый секретный ключ `ephem_sk` и симметричный ключ `sym_key` затираются в оперативной памяти с помощью `zeroize`.
8. Итоговый бинарный Envelope (длина $\ge$ 68 байт):
   `[KeyID: 8B] || [Ephem_PK: 32B] || [Nonce: 12B] || [Ciphertext + Tag: N+16B]`.

## Зашифрованный дисковый буфер

При отсутствии связи с центром события буферизуются в локальный файл:
- Файл содержит строки формата `Base64 (Standard)` от готового бинарного `Envelope`.
- На диске агента **никогда не сохраняются открытые JSON/JSONL логи** или метаданные атакующих.
- При восстановлении связи агент построчно вычитывает буфер и отправляет зашифрованные конверты в центр.
